# 출근길 알림 봇 설계 문서

작성일: 2026-11-23
상태: 사용자 승인 완료

## 0. 단계 (2026-11-24 변경)

- **1차 (지금 구현)**: 웹 화면(`http://localhost:8080`)에서 날씨, 미세먼지, 대표·환승 정류장 버스 도착, 등록된 지하철역 도착 정보를 확인한다. 정류장과 역은 화면 폼으로 등록·삭제한다.
- **2차 (보류)**: 텔레그램 명령, 매일 자동 알림. 아래 설계의 텔레그램·스케줄러 부분은 2차에 해당한다.

## 1. 목적

매일 아침 출근 전에 날씨, 미세먼지, 버스·지하철 도착 정보를 텔레그램으로 한 번에 받는다.
백엔드 개발 역량(외부 API 연동, 스케줄링, 사용자 입력 처리, 배포)을 키우는 것이 목표다.
비용이 발생하지 않는 구성을 원한다.

## 2. 접근 방식 (선택됨)

- **선택: 텔레그램 봇 + 스케줄러 알림**. 폰으로 바로 받을 수 있고, 외부 API 여러 개를 묶는 구조라 연동 역량을 키우기 좋다. 단, 2026-11-24에 1차는 웹 화면으로 먼저 만들고 알림은 2차로 미뤘다 (0절 참고).
- 기각: 웹 대시보드 (매일 열어 봐야 해서 실사용성이 낮음)
- 기각: 지출 기록 봇 (공공 API 활용 목표와 맞지 않음)

## 3. 범위

### 포함
- 날씨 (기상청 API, 설정한 위치 기준. 현재 기온·습도·강수 상태는 초단기실황, 오늘 최저·최고 기온과 출근 시간대 강수 확률은 단기예보)
- 미세먼지 (에어코리아 API, 설정한 거주 자치구의 대표 측정소 기준. PM10·PM2.5 수치와 등급)
- 대표 정류장 버스 도착 정보 (서울시 버스 API: 표지판 번호로 정류소 정보를 조회(`getStationByUid`)해 정류소 ID, 노선별 순번, 노선별 도착 정보를 한 번에 얻는다. 같은 번호에 정류소가 여러 개면 후보에서 고른다)
- 환승 정류장 버스 도착 정보 (등록된 것 전부)
- 지하철 도착 정보 (등록된 역 전부, 서울시 지하철 실시간 API)
- 텔레그램 명령으로 정류장·역·알림 시간 관리
- 매일 설정된 시간 자동 알림, `/지금`으로 즉시 조회

### 지역 정책 (2026-11-23 추가)
- 지역 입력은 전국 단위로 받는다 (예: `/지역 은평구 응암동`). 입력값을 위도·경도로 변환해 날씨와 미세먼지에 사용한다.
- 버스는 **서울 정류장만** 지원한다. 서울 외 정류장 번호를 입력하면 "현재 서울 정류장만 지원합니다"라고 안내한다.
- 지하철은 **역 마스터 목록에 있는 역 전체**(1호선 경기 구간 포함)를 지원한다. 실시간 API가 경기 구간 역도 응답함을 소요산 샘플로 확인했다.
- 버스 Provider는 지역별로 교체할 수 있도록 인터페이스로 분리한다. 경기도 등 다른 지역 API는 응답 확인 후 별도로 추가한다.
- 서울 버스 API와 서울 지하철 API의 응답 범위(경기 구간 포함 여부)는 구현 전에 실제 응답으로 확인하고, 그 결과에 따라 지원 범위를 다시 정한다.

### 제외 (이번 범위 밖)
- 다른 지역 버스 API (지역 정책에 따라 추후 별도 설계)
- 여러 사용자 지원 (본인 한 명만 사용)
- 웹 화면

## 4. 사용자 명령어

| 명령 | 설명 |
|------|------|
| `/대표정류장 {표지판번호}` | 출근 시 첫 이용 정류장 지정 (번호 변경 시 덮어씀). 같은 번호에 정류소가 여러 개면 후보에서 고른다 |
| `/환승정류장추가 {표지판번호}` | 환승 정류장 등록. 같은 번호에 정류소가 여러 개면 후보에서 고른다 |
| `/환승정류장삭제 {번호}` | 환승 정류장 삭제 |
| `/역추가 {역이름} {호선}` | 지하철역 등록. 역명과 호선은 역 마스터 목록(`subway-stations.csv`)과 정확히 일치해야 저장되며, 맞지 않으면 후보를 안내 (예: `새절` → `새절(신사)`) |
| `/역삭제 {역이름} {호선}` | 지하철역 삭제 |
| `/정류장목록` | 대표 정류장, 환승 정류장 목록 조회 |
| `/역목록` | 등록된 역 목록 조회 |
| `/알림시간 {HH:MM}` | 매일 알림 시간 설정 (기본값 08:00) |
| `/지금` | 알림 내용 즉시 조회 |

- 정류장은 표지판 번호(ARS)로 입력받는다. 같은 번호에 정류소가 여러 개면 정류장 이름, 경유 노선, 방면을 보여주고 번호로 고르게 한다.
- 후보가 1건이면 목록 없이 바로 확정한다.
- 등록 시 정류장 이름과 지나는 노선을 확인해 응답한다.
- 존재하지 않는 번호나 역 이름은 저장하지 않고 안내한다.

## 5. 알림 구성

1. 날씨, 미세먼지
2. 대표 정류장 버스 도착 정보 (대표 정류장이 없으면 "대표 정류장을 설정해 주세요" 안내)
3. 환승 정류장 버스 도착 정보 (등록된 것 전부)
4. 지하철 도착 정보 (등록된 역 전부)

지하철 표시 방식:
- 역마다 호선과 방향별로 묶어 표시한다.
- 방향별로 다음 열차 2개까지만 표시한다.
- 시간 표시: `barvlDt`가 0보다 크면 `N분 후 (전역명)`, 0이면 `arvlMsg2` 문구를 그대로 쓴다 (예: `[7]번째 전역 (양주)`, `전역 진입`). 소요산 샘플 응답 5건이 모두 `barvlDt = 0`이었다.

## 6. 기술 구성 (제안)

- 언어와 프레임워크: Java 17 이상, Spring Boot
- 텔레그램 연동: 롱폴링 방식 (별도 공개 서버 없이 로컬에서 실행 가능)
- 스케줄링: `TaskScheduler`로 알림 시간을 DB에서 읽어 동적으로 등록 (시간 변경 시 재시작 없이 반영)
- 저장소: 로컬 DB (SQLite 또는 H2). 등록한 정류장, 역, 알림 시간 저장
- 설정 파일: 인증키 두 종류, 텔레그램 봇 토큰, 날씨·미세먼지 위치 설정만 보관
  - 공공데이터포털 키: 날씨, 미세먼지, 버스 도착, 정류소 조회
  - 서울 열린데이터광장 키: 지하철 도착 전용 (공공데이터포털 키와 다른 키)
- 외부 호출: 실패 시 재시도 1회, 실패한 항목은 "조회 실패"로 표시하고 나머지는 정상 발송
- 캐싱: 날씨와 미세먼지는 같은 날 여러 번 호출하지 않도록 짧게 캐시

## 7. 비용

- 공공 API: 무료 (개발계정 일일 한도 내에서 사용)
- 텔레그램 봇 API: 무료
- 서버: 로컬 실행 또는 무료 티어 (배포 단계에서 결정)

## 8. 제약과 리스크

- 공공 API는 활용 신청 후 승인 시간이 걸리고, 심의 승인은 2~3일이 소요될 수 있다.
- 키 발급 직후에는 바로 호출되지 않을 수 있다.
- 인증키는 Encoding/Decoding 중 오류가 나지 않는 쪽을 사용한다.
- 지하철 역 이름은 같은 이름이 있을 수 있으므로 호선과 함께 저장한다. 역명은 역 마스터 목록(`subway-stations.csv`, 696개 역)의 `STATN_NM`과 정확히 일치해야 한다.
- 역 마스터 목록에는 1호선 소요산·의정부 등 경기 구간 역도 포함되어 있다. 소요산 샘플로 실시간 응답이 오는 것을 확인했다.
- 이사 후 버스 지역이 바뀌면 버스 모듈을 교체해야 한다.
- 미세먼지 측정소 근접 조회 API(`getNearbyMsrstnList`)는 응암동 TM 좌표를 넣었을 때 제주 측정소 3곳을 반환해 신뢰할 수 없다. 측정소는 근접 조회로 정하지 않는다 (아래 9번 참고).
- 에어코리아 실시간 측정 응답의 `dataTime`은 `"2026-11-23 24:00"`처럼 자정을 `24:00`으로 표기한다. 파싱 시 다음 날 00:00으로 변환해야 한다.

## 9. 제가 정한 기본값 (사용자가 바꿀 수 있음)

- 알림은 평일에만 보낸다.
- 알림 시간 기본값은 오전 8시다.
- 지하철은 방향별로 다음 열차 2개까지만 표시한다.
- 지하철 역은 이름과 호선을 함께 저장한다.
- 환승 정류장과 지하철 역은 별개로 관리한다.
- 미세먼지 측정소는 거주 자치구의 대표 측정소를 쓴다 (2026-11-24 확정). 응암동은 은평구이므로 `air-station: 은평구`로 설정한다. 이 측정소는 자치구 측정소 목록(CSV)에 있고, `stationName=은평구` 실시간 조회가 정상 응답함을 확인했다. 다른 구로 이사하면 설정값만 바꾼다.
- 미세먼지 실시간 조회는 `dataTerm=DAILY&numOfRows=1&ver=1.3`으로 호출한다. `ver=1.3`을 붙여야 PM2.5 값(`pm25Value`, `pm25Grade1h`, `pm25Value24`)이 응답에 포함된다.
- 날씨 기준 (2026-11-24 확정): 최저 기온(`TMN`)은 base 0200 단기예보에서, 최고 기온(`TMX`)은 가장 최근 발표 시각의 단기예보에서 가져온다. 격자 좌표(`nx`, `ny`)는 위도·경도에서 계산하며 API를 쓰지 않는다. 응답의 `PCP`, `SNO`는 "강수없음", "적설없음" 문자열이므로 0으로 처리한다.

## 10. 열린 질문 (구현 중 확인 필요)

- 같은 표지판 번호에 정류소가 여러 개 나오는 경우가 서울 데이터에 실제로 있는지 (구현 중 확인). 있으면 후보 선택 흐름으로 처리한다.
- 서울시 버스 인증키 발급 가능 여부: 노선정보 API 안내에 "국가정보자원관리원 화재(25.9.26.)로 신규 인증키 발급 불가, 기존 인증키 사용 가능"이라는 문구가 있다. 신청이 막히는지 확인 필요
- 지역 입력의 행정구역 → 좌표 변환 방식 (도로명주소 API 또는 행정구역 좌표표)
- 평일 여부를 명령으로 바꿀 필요가 있는지 (현재는 고정)
- 대표 정류장 노선 필터링 방식 (전체 노선 표시 vs 노선 선택)
